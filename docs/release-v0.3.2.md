# v0.3.2 / 协议 v9

## 兼容与升级

本次为 Windows 客户端修复，协议仍为 v9，报文和鉴权流程不变。v0.3.2 GUI/CLI 可以使用现有 v0.3.1/v9 服务端，已有服务端不必因此重新安装。v8 仍不兼容；从 v8 升级时需同步升级服务端及所有客户端。此前的鉴权变更见 [v0.3.1 说明](release-v0.3.1.md)。

## 命令输出和诊断

修复将 netsh 的 UTF-8 输出再次按 OEM 码页转换造成的乱码，例如“确定。”显示为“纭畾銆?”。新的共享 Windows 命令执行器优先保留严格有效的 UTF-8，支持带 BOM 的 UTF-8、UTF-16LE 和 UTF-16BE；传统编码回退明确记录 OEM/ANSI 码页，无法可靠转换的内容显示为有界转义字节。

命令采集最多保留 8192 字节加 4 字节编码前瞻，继续排空超额输出以免子进程阻塞；日志字段最多显示 2048 字节文本，保持完整 UTF-8 字符。诊断记录编码、码页、实际采集/观察到的字节及截断状态。解码只影响诊断文本，不会把退出码为零的操作改判为配置失败，也不会修改系统代码页。

未勾选高级选项时，房间策略保持 TCP=Raw UDP、UDP/其它流量=KCP、关闭 FEC、realtime、MTU 1400。输出编码与高级选项无关，也不能仅凭修复乱码认定所有入房故障已经解决。

## Windows 网卡就绪与取消

Windows 创建虚拟网卡后，地址可能仍处于 DAD Tentative 状态；不能把此时暂时不可用的路由误报为其它 VPN 抢占。GUI 和 Windows CLI 共用总计 10 秒的单调时钟截止时间，每次最多间隔 100 ms 取样，等待接口、IPv4 地址及 DAD Preferred 状态就绪，再核对目标虚拟成员、子网广播及限定广播的实际选路和源地址。检测到地址冲突等明确错误时提前失败；真正的 VPN/实体网卡路由冲突仍会阻止数据面启动。

GUI 等待期间保持可响应，建房/加入和参数编辑暂时锁定，离开操作切换为取消。就绪前不启动数据面、独立数据通道或成员延迟探测；成员变更暂存，到就绪后按最新成员建立中继。取消、服务端断开或替换连接会使迟到结果失效；失败清理资源并返回大厅，终结错误只报告一次。

托盘图标在首次显示前完成初始化，消除与网络配置无关的 `QSystemTrayIcon::setVisible: No Icon set` 警告。原有启动尺寸适配和管理员权限行为保留。

## 构建与验证边界

保留 Qt 5.9.9、MSVC 2015 x64、DPI 启动适配和 Windows 管理员权限清单。Windows GUI 和 Windows CLI 共享本次命令输出修复；Linux 服务端网络实现保持不变。正式资产仍要求同一 tag、提交及统一 SHA256 校验和。

自动化覆盖 Unicode/传统编码、中文及 emoji 的采集/日志截断边界、超时后的不完整字符，以及解码不改变操作状态；网卡就绪、GUI 和 CLI 编排使用模拟状态覆盖延迟就绪、取消、超时、冲突、成员通知缓存及资源清理。另覆盖旧适配器排队错误隔离，以及等待期间错误与 Ready 竞争的情况。

2026-10-26 本机验证使用 Qt 5.9.9 / MSVC 2015 x64，16 项 Windows CTest 全部通过。旧版实测在 IPv4 DAD 仍为 Tentative 时于约 3 秒退房；新版 GUI 在同一电脑及现有 v9 服务端上约 3.5–3.7 秒后就绪，默认建房、退出后多次重建成功。GUI 另通过本机无 TUN 成员测试服务的加入房间验证。Windows CLI 使用同类仅监听本机的协议 v9 测试服务及无 TUN 成员，分别通过默认建房、退出后重建、加入房间和等待期间取消；四次防火墙添加均对应一次删除。

独立提权 Wintun 测试使用专属临时网卡及不重叠网段，在约 3.7 秒就绪后实际捕获普通单播、子网广播及有限广播的 UDP 测试包，并确认网卡、广播路由及防火墙规则清理。上述本机测试不代表真实多机游戏互通已验证；多机路由、防火墙策略和游戏互通仍需现场验证。

手动 GUI 包命名为 `vlan-gui-windows-x86_64-v0.3.2.zip`；`SOURCE.txt` 记录 `Release tag: v0.3.2`、该正式 tag 的完整构建提交和 `Protocol version: 9`。发布工作流继续在全部资产和校验完成前保留草稿。
